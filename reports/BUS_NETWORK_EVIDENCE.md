# 마을버스 배차·BMS 보완분석

기준일: 2026-08-13
분석 ID: `official_bus_headway_bms_crosscheck_v1`

## 결론

2025-08-25 고양시 정류장 파일에 `(마을)`로 표기된 고유 노선 86개를 분모로 다시 검증했다.

- 공식 배차 CSV에서 정규화된 노선번호 후보가 있는 노선은 **82개(95.3%)**다.
- 정규화 전 원문 노선번호 완전일치는 **30개**이며, 선행 0·끝 괄호 표기를 규칙대로 맞춘 뒤 후보 범위가 82개가 됐다.
- 이 중 공식 행이 하나뿐인 노선은 **72개(83.7%)**다.
- **10개(11.6%)**는 같은 번호의 공식 행이 2개라, 현행 노선 ID 또는 운행업체 확인 전에는 단일 배차값으로 선택할 수 없다.
- 공식 배차 CSV에 후보가 없는 노선은 **4개(4.7%)**다: `15-1(구파발)`, `15-1(지축)`, `15A`, `15B`.

따라서 발표에서는 “82개 배차 확정”이 아니라 **“86개 중 82개는 공식 배차표에서 번호 후보를 확인했고, 단일 공식행으로 바로 연결되는 것은 72개”**라고 말해야 한다.

## 배차 매칭 방법

노선번호 비교키는 다음 순서로만 만들었다.

1. Unicode NFKC 정규화
2. 앞뒤 공백 제거 및 영문 대문자화
3. 끝의 괄호 부가표기 제거: `055(통합) → 055`, `043(원당역) → 043`
4. 숫자로 시작하는 노선의 숫자 접두부 선행 0 제거: `055 → 55`, `011 → 11`
5. 정규화 키의 완전일치만 허용

부분문자열·유사도·검색결과 전체 fallback은 사용하지 않았다. 같은 키에 공식 행이 2개면 두 원문을 모두 보존하고 단일값 산출에서 제외했다.

복수 후보 10개는 `011`, `055`, `057`, `065`, `066`, `067`, `069`, `097`, `098`, `099`다. 일부는 종점명만 보아도 마을버스 후보를 추정할 수 있지만, 추정으로 확정하지 않았다.

## 배차값 해석 경계

공식 `배차간격`은 `06~10(08~11)`처럼 작성된 **자유기술 계획값**이다. 괄호가 평일·주말 또는 첨두·비첨두 중 무엇을 뜻하는지 파일 자체에 구조화된 정의가 없다. 따라서 이번 보완분석은 다음을 하지 않았다.

- 평균 대기시간 계산
- 평일·주말 또는 시간대 분해
- 실제 운행준수율·결행률 추정
- 정류장별 체감대기시간 주장

배차 CSV 기준일은 2024-12-31, 마을노선 분모를 만든 정류장 파일 기준일은 2025-08-25다. 노선 개편 가능성이 있으므로 현재 운영값으로 단정할 수 없다.

## BMS 경유정류소 연결 결과

2023 BMS 노선명에서 같은 정규화 번호의 `route_id` 후보를 먼저 만들고, 각 후보의 정류장 ID와 2025 고양시 정류장 중 해당 마을노선이 표기된 정류장 ID의 교집합을 계산했다. 양의 교집합이 있는 유일 `route_id`만 연결했다.

- 전체 86개 중 보수적으로 연결된 노선: **7개**
- 연결되지 않은 노선: **79개**
- 공개 가능한 연결 결과: **56개 노선-정류장 행**, 중복 좌표를 합치면 **47개 고유 위치**

낮은 연결률은 실패를 숨긴 값이 아니라 시점 차이를 드러내는 품질 결과다. 2023 BMS와 2025 정류장 표기의 노선명·노선 ID·정류장 ID가 충분히 일치하지 않는다. 이 7개 연결도 **현행 전체 노선형상**이 아니라 역사적 교차검증 표본으로만 사용해야 한다.

## 노선형상 파일 경계

[경기도 BMS 노선 경로이력](https://data.gg.go.kr/portal/data/service/selectServicePage.do?infId=B87V4OBIG76T6N59I3SM33067357&infSeq=1)은 공식 메타데이터상 2025-10-31 기준, 268,567,781바이트 ZIP으로 공개돼 있다. 노선 ID, 경로점 순서, X/Y 좌표 필드 명세는 확인했지만 이번 실행에서는 파일을 내려받지 않았다.

- 경기도 전체 대용량 파일이고, 먼저 2023 노선 ID를 2025 고양 마을노선에 안정적으로 연결해야 한다.
- 공식 메타데이터에 X/Y 좌표계가 명시돼 있지 않아 CRS를 임의 가정하면 안 된다.
- 현재 7개 역사적 연결만으로 선형을 그리면 “현재 고양 마을버스 GIS”처럼 오해될 수 있다.

따라서 MVP 지도에는 기존 2025 정류장 좌표를 유지한다. 이번 BMS 56개 노선-정류장 행(47개 고유 위치)은 지도에 현행 노선처럼 표시하지 않고, 요약 카드의 `역사적 연결 확인` 근거로만 사용한다.

## 공개 산출물

- `headway_route_matches.csv`: 86개 전체 후보 상태와 공식 원문
- `headway_multiple_candidates.csv`: 복수 공식행 10개
- `headway_unresolved_no_candidate.csv`: 후보 없음 4개
- `bms_route_linkage.csv`: 86개 역사적 BMS 연결 결과
- `bms_linked_stop_points.csv`: 보수적으로 연결된 56개 노선-정류장 행(47개 고유 위치). 공개본에서는 노선 ID·정류장 ID·정류장명을 제거하고 노선번호·좌표·과거 순번 범위·행정동만 남김
- `analysis_summary.json`: UI·발표용 핵심 집계와 금지 해석
- `source_manifest.csv`, `lineage.csv`, `data_dictionary.csv`, `data_quality.csv`: 출처·계보·사전·검증

재현 코드는 `scripts/fetch_official_bus_evidence.py`와 `scripts/build_bus_network_evidence.py`다. 수집기는 키 없이 공식 경로만 사용하고, 다른 바이트의 기존 원본을 덮어쓰지 않는다.

### 수집 중 확인한 오류와 해결 원리

- BMS ZIP 직접 경로는 기본 PowerShell/curl 사용자 에이전트에서 400 또는 500을 반환했다. 공식 브라우저와 같은 일반 Chrome 사용자 에이전트를 명시하자 `application/octet-stream`과 정상 ZIP이 반환됐다. 수집기는 ZIP magic과 내부 CSV 헤더를 다시 확인한다.
- BMS 노선 매핑 Sheet는 세션 없이 다운로드 URL만 호출하면 “정상적인 접근이 아닙니다” HTML을 반환한다. 수집기는 공식 상세 페이지를 먼저 열어 세션 CSRF를 받고, 같은 쿠키·Referer로 CSV를 내려받은 뒤 헤더와 4,492개 비어 있지 않은 행을 확인한다.
- 위 토큰은 공개 API 인증키가 아니라 세션용 CSRF이며 manifest·공개 산출물에 저장하지 않는다. 실제 인증키는 사용하지 않았다.

## 발표·MVP 적용 문장

> 고양시 정류장 표기에서 확인한 마을버스 86개를 공식 2024년 배차표와 교차검증한 결과, 82개는 노선번호 후보를 확인했습니다. 다만 같은 번호의 공식 행이 2개인 10개는 현행 노선 ID 확인 전 단일 배차로 확정하지 않았고, 4개는 후보가 없어 후속 확인 대상으로 분리했습니다.

이 수치는 실제 돌봄대상자, 62개 서비스 이용, DRT 운행성과를 의미하지 않는다. 정책 대시보드에서는 `공식 배차 후보 연결률`과 `추가 확인 필요`를 보여주는 데이터 품질 단계로만 사용한다.
