## 보완 목표

> 저희가 확인한 공개자료에서는, 돌봄 수요와 실제 이동 가능성을 함께 검증한 결과를 찾지 못했다.

MVP와 발표는 이 문제를 한 문장으로 설명하고, 공개데이터로 확인한 신호와 추가로 확인해야 할 실제 이동자료를 구분한다. 결과는 자동 도입 추천이 아니라 현장조사와 데이터 요청 순서다.

## 데이터 확보 원칙

1. 공식 CSV·공식 API를 우선한다.
2. 공개대화에 노출된 인증키는 사용하지 않는다. 재발급 키는 관리자 데이터 연결 화면의 현재 탭 세션에만 입력한다.
3. API가 제공하는 노선·정류소·시간표는 정적 공급자료다. 실제 이용·배차성공·대기·OD를 대신하지 않는다.
4. 실제 대상자·62개 서비스·호출·운영비는 기관 협조 자료로 분류한다.
5. 자료가 없으면 합성값으로 채우지 않고 `계산 보류`와 필요한 입력을 화면에 표시한다.
6. 경로당은 현재 공식 웹 화면 **593건**, 재현 가능한 공식 Excel **594행(파일 내부 2026년 6월 기준)**을 함께 표시한다. 1건의 공식 채널 버전 차이를 숨기지 않는다.
7. 공식 똑버스는 식사·고봉·덕은·향동 **4개 운영권역**이며, 이를 분석의 행정동 수와 동일시하지 않는다.

## 잘못된 단순 ΔRI를 사용하지 않는 이유

현재 RI는 100m 격자에서 병·의원·약국까지의 직선거리 보행 대리값이다. 버스 정류장 접근, 대기, 환승, 실제 버스 주행시간이 RI에 포함되어 있지 않다. 따라서 `정류장 접근 페널티 제거`나 기존 RI 단순 차감은 재현 코드와 맞지 않는다.

피드백의 전·후 수치 요구는 다음 조건을 공개한 접근성 시나리오로 대응한다.

- 비교 목적지: 현재 공개분석과 같은 병·의원·약국
- 기준선: 직선보행 대리시간
- 시나리오: 승차지점 접근시간 + 대기시간 + 차량 이동시간
- 대기시간: 복수 가정으로 범위 표시
- 결과: 후보별 일반화 이동시간·30분 이내 의료접근 격자 비율의 시나리오 범위
- 해석: DRT 실제 효과가 아니라 현장자료를 받기 전 가정 민감도

관산동 결과는 다음과 같다.

- 보행 대리 30분 면적커버리지: `88.5%`
- 대기 5·10·15분 가정 시나리오: `99.6~100.0%`
- 중앙 일반화시간: `16.2분 → 14.1~24.1분`
- 중앙격자 손익분기 대기시간: `7.2분`

15분 대기 가정에서는 중앙 일반화시간이 기준보다 `+7.8분` 길어질 수 있다. 따라서 이 분석은 “DRT를 넣으면 개선된다”가 아니라 “실제 대기시간을 반드시 확보해야 한다”는 피드백 대응 근거다. 커버리지는 사람 비율이 아닌 동일면적 100m 격자 비율이다.

## 완료 판정

- MVP 첫 화면에서 15초 안에 문제·분석·결과물의 역할을 설명한다.
- 화면당 핵심 주장 1개, 시각 1개, 다음 행동 1개만 둔다.
- 피드백 8개 항목에 `완료·부분완료·자료 필요` 상태가 표시된다.
- API 수집자료에는 기준일·요청·응답상태·정확 매칭·미해결 목록이 남는다.
- 실제 자료가 없으면 효과값·수혜자 수·도입 확정이 표시되지 않는다.
- 단위·브라우저·320px 모바일·200% 확대 검증을 통과한다.
